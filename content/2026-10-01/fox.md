## 今日發現

多代理與長任務工作流最近把「handoff」從工程術語推回日常桌面：研究與實務都指出，跨 session、跨人或跨 agent 交接時，最容易丟失的不是檔案本身，而是意圖、約束、已承諾的變更、證據來源，以及「為什麼暫停」這一個命名好的問題。常見做法是寫一份結構化交接文件，而不是把整段對話壓縮後丟給下一個窗口——後者既貴，又容易把探索過程中的雜訊與未經驗證的假設一起帶過去。好些團隊已經把交接文件當成像 API 契約一樣的邊界產物：下一階段只認契約內容，不重播上游的推理過程。

同一問題也折磨純人類的知識工作。一場會議結束、兩個專案之間來回切換，人們往往靠記憶與聊天片段重啟狀態；深度情境切換的恢復成本常以刻鐘計，一天數次切換就能吃掉一兩個小時的有效專注。值班交接、事故交班本來就有「發生了什麼、處理到哪、下一班要注意什麼」的傳統，只是多數個人工作流從未把它縮成可重複的最小單位。AI 不過是把這條舊紀律重新變得不可省略：對方沒有你腦中的半成品上下文，交接必須外化，否則每一次新窗口都在付同樣的暖場稅。

## Idea 本身

做一張極輕的「上下文交接卡」（Context Handoff Card）：在會議結束、專案暫停，或把工作交給另一個人／另一個 agent 之前，強制產出一張固定欄位的短卡——不是會議紀錄，也不是進度日誌，而是**下一個接手者立刻開工所需的最小狀態**。

目標用戶是同時跑多專案的知識工作者，以及開始把任務拆給個人 AI agent 的人。它要解決的痛點很具體：重述「我們做到哪」浪費的暖場時間、把已否決方案重新討論一遍、以及 agent 在新 session 裡用錯約束或重做已完成步驟。換言之，卡的價值不在「寫得漂亮」，而在**讓下一決策不必重播歷史**。它也不是第二套待辦清單：待辦告訴你「還有什麼」，交接卡告訴你「接手時必須知道什麼」。

卡片建議固定五欄，寫不滿就留空，但欄位名稱不變：

1. **目標（一句）**：這段工作要完成什麼，用請求者原話或最接近原話的一句。
2. **約束**：不可改的邊界（期限、預算、技術棧、已否決選項、權限範圍）。
3. **已落地狀態**：已經寫進系統／檔案／PR 的變更；只列事實，不寫心情。
4. **證據與來源**：關鍵結論各自指向哪份筆記、連結、測試結果或對話——引用路徑，不貼長文。
5. **暫停問題＋下一步**：為什麼停在這裡（一個命名好的問題），以及接手後的第一個可執行動作與停止條件。

長度上限刻意設短：約 15–40 行，或相當於 200–400 token 的資訊密度。超過一頁就代表把工作日誌誤當成交接卡——日誌可以另存，卡上只留結論與下一步。人與 agent 讀同一張卡，比各自維護一份「腦內摘要」更便宜、也更可稽核。欄位固定還有一個附帶好處：接收端可以用同樣的檢查清單逐項確認，而不是從散文裡猜哪句是約束、哪句是建議。

## 點樣落地

1. **定模板**：在筆記庫或專案根目錄放 `HANDOFF.md`（或 `handoffs/YYYY-MM-DD-topic.md`），五欄標題寫死；再附一份「已填範例」對照，降低第一次下手的猶豫。範例要寫得像真的一天結束時的卡，而不是行銷文案。
2. **綁觸發點**：三個強制寫卡時機——日曆會議結束後兩分鐘內、切換專案標籤前、把任務交給 agent／同事前。可用快捷指令或一句固定口令：「先寫交接卡，再換上下文」。觸發點比工具重要：沒有觸發，模板只是死檔。
3. **人機同一格式**：人寫給人、人寫給 agent、agent 回報給人，都用同一張卡。接收端只讀卡上欄位，不重播整段會議錄音或完整對話歷史；需要細節時再沿證據欄回溯。這等於把「上下文隔離」從口號變成可操作規則。
4. **與記憶分工**：長期偏好、工具指令、帳戶習慣放進穩定 memory；交接卡只承載「做到哪、下一步是什麼、有什麼坑」。兩者互補，不要互相替代，也不要把卡上的臨時狀態寫進永久檔，否則永久檔會被過期進度污染。
5. **一週後再談自動化**：先手動填滿一週，確認欄位夠用；再讓 agent 在會後從筆記／錄音摘要草稿卡，由你改兩處後存檔——自動化永遠排在模板穩定之後，否則只是加速製造垃圾摘要。若某欄連續一週都空，考慮刪掉或合併，而不是硬撐五欄。

## 風險同取捨

- **寫卡摩擦**：若每次要寫半小時，習慣會死。必須用字數上限與「留空可接受」對抗完美主義；寧可五欄各一行，也不要一篇散文。真正昂貴的是不寫卡之後的重講與返工。
- **與會議紀錄混淆**：紀錄服務歸檔與問責；交接卡服務下一決策。混在一起會膨脹，也會把敏感討論全文帶進下一個 context。分開存放，必要時互相連結即可。
- **過時卡**：舊卡若未標時間戳，接手者會當真相。每張卡頂部寫 `as-of` 時間；開新工作時複製為新卡，舊卡歸檔不覆寫。過期卡比沒卡更危險，因為它看起來很完整。
- **證據欄被濫用成全文轉貼**：貼上大段外部內容既浪費，也有把不可信指示帶進下一窗口的風險。慣例是連結與檔名，必要時一句摘要；來源與主張分開寫，接收端才知道該信任到什麼程度。
- **組織文化阻力**：「多此一舉」的感覺真實存在。先從自己與 agent 的邊界練起，再用「少重講十分鐘」當說服材料，而不是先推全公司規範。個人有效之後，再談團隊共享模板；強制推廣而沒有可感收益，只會換來空殼文件。

## 一週內可驗證小實驗

選兩個你本週必定會切換的專案（或一場會＋一次 agent 長任務）。每次切換前用同一模板寫一張交接卡，切回時只讀卡、禁止重翻舊聊天超過三分鐘。用一張極簡表格記下：切換時刻、重入到第一個有效動作的分鐘數、有無因遺忘約束而返工。七天後對照實驗前三天的同類切換；若樣本太少，至少累積六次切換再下結論。

**成功標準**：與實驗前三天相比，中位重入時間下降至少 40%，或因遺忘約束造成的返工次數降到零。
