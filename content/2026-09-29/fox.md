## 今日發現

個人 AI 正從「打開聊天框問一句、答完就散」走向跨 session 的 persistent intent agents：它們記得你未完成的意圖，能在背景把多步工作流往前推。公開討論裡，競爭點漸漸從「誰更會寫」轉成信任、權限邊界，以及 human-in-the-loop 何時必須介入——也就是：當 agent 代你做事時，你一週後還能不能講清楚「為什麼當時允准這一步」。

另一條平行線是個人知識管理（PKM）的痛點轉移。人們少再抱怨「找不到筆記」，更多是「維護成本太高、第二大腦變成第二待辦」。業界可見的方向是：知識最好作為工作副作用自動累積——ambient context、local-first 的 context engine、共享 markdown vault，以及多個 agent 透過 MCP 讀同一份知識庫。筆記不再是表演式寫作，而是基礎設施。

把兩條線疊在一起，會冒出一個很具體、卻很少被產品化的缺口：我們每天做很多「小而重要」的決定——回哪封信、砍哪個功能、選哪家供應商、要不要延期——但很少留下可覆核的理由。一週後只剩結果與情緒殘渣，沒有收據。會議紀錄記「做了什麼」，待辦記「還要做什麼」，兩者都不回答「當時為何這樣選」。當 intent agent 開始代勞，這個缺口會放大：沒有可追溯依據，你就只能選擇盲目信任，或每次都重新審問上下文。

## Idea 本身

做一個極輕的「決策收據」（Decision Receipt）：當你（或你的個人 agent）完成一次被標記為「重要」的決定時，系統自動寫下一行結構化紀錄——不是長篇反省文，也不是情緒打卡，而是一張可掃讀、可覆核的短收據。欄位固定，刻意薄：

- **決定**：一句話，寫清取捨本身（例如「本週不做新落地頁，改修導航漏斗」）
- **理由**：兩到三條，每條不超過一行；允許「資訊不足，先選可逆路徑」
- **被捨棄選項**：至少一行，寫你沒選的那條路，降低事後美化
- **來源鏈**：指向觸發這次決定的訊息、文件、數據截圖或對話摘要（本地路徑優先）
- **覆核日**：預設七天後；到期只推一張卡，不逼你寫長文
- **狀態**：待覆核／已確認／已推翻（推翻時必須再寫一行新理由，並鏈到新收據）

服務對象是知識工作者、自僱者、小團隊負責人，以及已經開始用個人 agent 代勞的人。他們不缺靈感與工具，缺的是**決策失憶的低成本補丁**：把「為什麼」變成工作流副作用，而不是另一本要刻意維護的日記。也可把收據想成給未來自己與協作者的「最小交接物」——不必重開一場會，就能接上脈絡。

本品刻意避開情緒隱喻與心情打卡：這裡記的是選擇與依據，不是感覺氣候。它也不是傳統決策矩陣（那類工具要求你事先打分、權重、多準則比較）；收據承認多數日常決定是「夠用就走」，只要求事後可追溯。AI 的角色收斂：只負責從上下文草稿出收據、標出來源缺口、到覆核日推送一張卡；最終勾選「確認／推翻」必須由人完成。目標不是「幫你做更好的決定」，而是讓一週後的你，仍能在三十秒內還原當日的決策鏈，並在需要時把同一張卡丟給同事或下一個 agent 接棒。

## 點樣落地

1. **定義觸發邊界**：先列十類「值得留收據」的決定——例如超過兩小時工時的取捨、對外承諾、金錢或合約、產品範圍砍增、授權 agent 代發對外訊息。其餘瑣事一律不記。硬設每週上限（例如十二張），超過就強制合併或丟棄最輕的，避免收據牆。
2. **最小資料模型**：本地 markdown 或 JSONL 即可。每張收據一個短檔，或 vault 裡以日期為序的一行 frontmatter。來源鏈用相對路徑指向既有筆記、郵件匯出、agent 對話存檔。預設不上雲；若要同步，只同步脫敏後的摘要欄位。
3. **人機分工**：個人 agent 或快捷指令在偵測到「決定語氣」、或你手動打 `/receipt` 時草擬草稿；你只花三十秒刪改並確認。覆核日用行事曆或本地排程推「請覆核」卡：勾確認則鎖檔；勾推翻則強迫寫新理由並自動開一張後續收據。
4. **一週摘要，不是儀表板**：週日只輸出「本週 N 張、其中 M 張被推翻」與三個高頻理由關鍵詞，外加「來源缺失」清單。不做分數、不做人格標籤、不做連續打卡獎懲——只提供可掃描的覆盤素材，方便你決定下週要收緊哪些觸發類別。
5. **先做 CLI／筆記插件原型**：Telegram bot、快捷指令或 Obsidian 命令夠用。等觸發規則穩定，再與 intent agent 的權限閘門串接——例如：agent 代發對外承諾前，必須存在一張當日已確認的收據 ID，否則停在 human-in-the-loop。

## 風險同取捨

- **過度記錄**：什麼都留，系統會崩成第二份待辦。解法是類別白名單＋每週上限；寧願漏記，也不要淹沒。成功的收據系統看起來偏空，而不是偏滿。
- **事後合理化**：人會替已做決定找漂亮理由。強制「被捨棄選項」欄，並允許「當時資訊不足」作為合法理由，可降低表演壓力；覆核日若發現來源鏈指向過期數據，應高亮而不是假裝永遠有效。
- **隱私**：來源鏈常連到郵件、合約、對話。預設本地；分享週摘要時必須剝離路徑、金額與人名。Agent 讀 vault 應走明確授權範圍，而不是隱性全盤掃描——這與 intent agent 浪潮裡的信任競爭點一致。
- **與決策日記混淆**：若你本來就愛每週寫長文覆盤，薄收據可能顯得過輕。此時應把產品邊界收窄到「服務 agent 代勞與對外承諾」，而不是硬推全民打卡。
- **假精確**：收據給人「已經想清楚」的錯覺。文案與 UI 應強調：這是可追溯草稿，不是正確性證明；推翻是一等公民操作，不是失敗。若一週內推翻率長期為零，反而要檢查是不是只在記「不會錯」的決定——那會讓系統失去覆盤價值。
- **協作摩擦**：若小團隊共用 vault，誰有權改狀態、誰能看來源鏈，要先定簡單規則（例如：作者可推翻，旁人只能評論）。否則收據會變成另一種會議戰場。

## 一週內可驗證小實驗

不必寫程式。選你本週五個「會影響往後至少一天工作」的決定（開會結論、範圍取捨、是否回覆或延期皆可）。每做完一個，立刻在備忘錄用固定模板寫五行：決定／理由×2／被捨棄選項／來源（檔名或對話日期）／覆核日＝＋7 天。第七天只花十分鐘重讀這五張紙上收據，對每張勾「仍成立／已推翻或需修正」。

**成功標準**：若五張裡至少有四張你能在三十秒內講清「當時為何這樣選」，且至少一張在覆核時被標成「已推翻或需修正理由」，Idea 就值得做成最小自動化原型；若五張都覺得多餘或寫完從不回頭，就縮小觸發類別再試三天，而不是先加功能。
